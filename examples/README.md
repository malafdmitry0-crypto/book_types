# Одна библиотека алгоритмов — разные реализации

Дополнительная модель User для сравнения API во второй части [основного курса](../book/README.md). Это учебный модуль, а не предлагаемая замена стандартной библиотеке.

[Все последовательные вызовы](example_test.go) · [Единый каталог кода](../lessons/README.md)

## Семейства API

| Подход | Find / All / Map |
|---|---|
| Конкретные типы | `FindUser`, `AllUsers`, `MapUserNames` |
| Индексы и замыкания | `FindIndex`, `AllIndex`, `MapInto` |
| Поведенческие интерфейсы | `FindInterface`, `AllInterface`, `RunMap` |
| Пустой интерфейс | `FindAny`, `AllAny`, `MapAny` |
| Reflection | `FindReflect`, `AllReflect`, `MapReflect` |
| Генерация | `FindUsersGenerated`, `AllUsersGenerated`, `MapUsersGenerated`; аналогично для int |
| Параметры типов | `Find`, `All`, `Map` |
| Итераторы | `FindSeq`, `AllSeq`, `MapSeq` |

Для срезов Find возвращает индекс или -1; для Seq — значение и bool. All на пустом входе истинен. Eager Map сохраняет nilness и порядок; Collect поверх Seq возвращает nil для пустой последовательности. Различия контрактов объяснены в главах.

## Запуск

Нужен Go 1.23 или новее из-за `iter` и range-over-func. Внешних зависимостей нет. Из этой папки:

```sh
go test ./...
go vet ./...
go generate ./...
```

Или из корня репозитория:

```sh
go -C examples test ./...
```

`go generate` обновляет только `generated_algorithms.go`. Генератор использует стандартные `text/template` и `go/format`; файл включён в учебник, поэтому для обычного запуска тестов генерация не нужна.

## Что проверяют тесты

- Общий результат разных подходов на nil, пустом и непустом входе.
- Порядок и nilness результата eager Map.
- Раннюю остановку Find и All по количеству вызовов callback.
- Отказ reflection API на неверных аргументах, включая пустые срезы.
- Распространение panic из callback.
- Отложенное вычисление и остановку источника у MapSeq.
- Нулевое значение как успешный результат FindSeq.
- Разные типы E/R и сохранение определённого срезового типа у Clone.

Общий контракт проверен Go 1.25.4. Сами исторические алгоритмы не заявлены как протестированные на каждом старом toolchain. Benchmark-цифры не приводятся: методика сравнения и задания находятся в последней главе основного курса.
