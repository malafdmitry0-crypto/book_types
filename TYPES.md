# Типы и общие методы

Методы добавлены в существующие пакеты. Это основа для последующих упражнений с интерфейсами и дженериками; общие алгоритмы поверх этих типов пока не добавлены.

## Общий контракт

`T` в таблице обозначает конкретный тип получателя. Все методы имеют получатель по значению и не изменяют исходное значение.

| Метод | Fraction | BoxInt | IntValue | Money | Vector2 | Version |
|---|---|---|---|---|---|---|
| `Validate() error` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `String() string` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `IsZero() bool` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `Equal(T) bool` | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| `Compare(T) (int, error)` | ✓ | ✓ | ✓ | ✓ | — | ✓ |
| `Add(T) (T, error)` | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| `Sub(T) (T, error)` | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| `Mul(T) (T, error)` | ✓ | ✓ | ✓ | — | — | — |
| `Div(T) (T, error)` | ✓ | ✓ | ✓ | — | — | — |
| `Neg() (T, error)` | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| `Abs() (T, error)` | ✓ | ✓ | ✓ | ✓ | — | — |

Дополнительные методы:

- `Vector2.Scale(float64) (Vector2, error)` — умножение на скаляр.
- `Vector2.Dot(Vector2) (float64, error)` — скалярное произведение.
- `Vector2.Norm() (float64, error)` — евклидова длина.
- `Version.NextPatch()`, `NextMinor()`, `NextMajor()` — результат `(Version, error)`; повышение старшего компонента обнуляет младшие.

## Как измеряется совпадение

Сравниваем имена и формы сигнатур после замены конкретного типа получателя на `T`. Процент — число общих методов, делённое на число методов в объединении двух наборов. Конструкторы и неэкспортируемые вспомогательные методы не считаются.

- `Fraction`, `BoxInt`, `IntValue`: 11 общих методов из 11 — **100%** между каждой парой.
- `Money` и любой из этих трёх типов: 9 из 11 — **81,8%**.
- Векторы и версии имеют отдельные предметные операции; порог не навязывается каждой паре, как и было оговорено.

`TestMethodOverlap` проверяет формы сигнатур и порог. `TestCommonArithmetic` также использует один generic-контракт с одиннадцатью методами для дроби и двух целочисленных типов.

Это не означает, что `Add(Fraction)` и `Add(Money)` являются одной конкретной сигнатурой Go. Для общего интерфейса понадобится параметр типа, например `Adder[T]` с методом `Add(T) (T, error)`.

## Семантика и ошибки

`Compare` возвращает -1, 0 или 1. При ошибке результат операции нужно игнорировать. `Equal` и `IsZero` для невалидных значений возвращают false; `Validate` позволяет получить причину. Поэтому равенство обладает ожидаемыми законами на допустимых значениях, а не на произвольных невалидных литералах.

**Fraction.** `New(n, d)` сокращает дробь и делает знаменатель положительным. Методы принимают также несокращённые литералы и отрицательные знаменатели. Равенство и сравнение математические: `1/2` равно `2/4`. Арифметика использует точные промежуточные вычисления через `math/big`, затем проверяет, что сокращённые числитель и положительный знаменатель помещаются в int64. Конструктор может отвергнуть литерал, чья каноническая форма не помещается. Сравнение таких литералов не требует помещения канонической формы в поля. Нулевой знаменатель недопустим; корректный ноль — `Fraction{Denominator: 1}`. `String` печатает сокращённую дробь, целое без `/1` или диагностику неверного значения.

**BoxInt и IntValue.** Методы проверяют переполнение int64; деление отбрасывает дробную часть к нулю. Деление на ноль и `MinInt64 / -1` возвращают ошибки. Встроенные операторы IntValue остаются обычными операторами Go: проверяемый контракт относится именно к методам. Нулевое значение обоих типов корректно.

**Money.** Amount хранится в минимальных единицах валюты. Validate проверяет три заглавные ASCII-буквы, а не наличие кода в валютном реестре. Add, Sub и Compare требуют одинаковой валюты. Equal между разными валютами возвращает false. Отрицательные суммы допускаются; переполнение является ошибкой. String явно пишет минимальные единицы, не предполагая два десятичных знака. Ноль требует валюты: `Money{Currency: "USD"}`. Конвертация валют, округление, умножение и деление денежных сумм друг на друга не выполняются.

**Vector2.** Координаты и результаты должны быть конечными: NaN и бесконечность отвергаются. Equal использует точное равенство float64; приближённое сравнение не вводится автоматически. Общего Compare нет: сортировку по длине или координатам выбирает вызывающий. Нулевой вектор корректен.

**Version.** Любая комбинация трёх uint32 допустима. Порядок лексикографический: major, minor, patch. Увеличение компонента проверяет переполнение; сложения версий нет. Предрелизные метки и метаданные сборки не поддерживаются, поэтому это не полная модель SemVer.

## Проверки

```sh
go test ./...
go vet ./...
```

В текущем окружении проверки выполнены установленным Go 1.25.4. Тесты покрывают общий арифметический контракт, сигнатуры, сокращение дробей, точные промежуточные вычисления, переполнение, разные валюты, невалидные значения, векторные операции и порядок версий.

Модуль `examples` остаётся отдельным учебным модулем с прежними алгоритмами.
