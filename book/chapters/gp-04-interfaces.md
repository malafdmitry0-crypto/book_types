# 4. Интерфейсы: алгоритм через минимальный набор операций

> Интерфейс позволяет алгоритму не знать представление данных, если все нужные действия выражены методами.

## Сначала настоящий пример: sort.Interface

Исторический `sort.Sort` принимает объект с методами `Len`, `Less`, `Swap`. Он не извлекает «универсальный элемент». Для сортировки достаточно узнавать длину, сравнивать позиции и переставлять их. Именно поэтому алгоритм может работать с разными коллекциями без знания типа элемента.

```go
// import "sort"
type UsersByAge []User

func (s UsersByAge) Len() int           { return len(s) }
func (s UsersByAge) Less(i, j int) bool { return s[i].Age < s[j].Age }
func (s UsersByAge) Swap(i, j int)     { s[i], s[j] = s[j], s[i] }

// sort.Sort(UsersByAge(users))
```

Конверсия в `UsersByAge` добавляет доступ к методам определённого типа; данные среза при этом остаются общими. Общая сортировка управляет порядком вызовов, адаптер выполняет конкретные операции. См. [sort.Interface](https://pkg.go.dev/sort#Interface).

## Такой же ход для Find и All

```go
type MatchSequence interface {
    Len() int
    Match(int) bool
}

type UserQuery struct {
    Values []User
    Pred   func(User) bool
}

func (q UserQuery) Len() int         { return len(q.Values) }
func (q UserQuery) Match(i int) bool { return q.Pred(q.Values[i]) }
```

```go
func FindInterface(src MatchSequence) int {
	for i := 0; i < src.Len(); i++ {
		if src.Match(i) {
			return i
		}
	}
	return -1
}
```

```go
func AllInterface(src MatchSequence) bool {
	for i := 0; i < src.Len(); i++ {
		if !src.Match(i) {
			return false
		}
	}
	return true
}
```

Вызовы: `FindInterface(UserQuery{users, adult})` и `AllInterface(UserQuery{users, active})`. Реализация интерфейса определяется набором методов; отдельного объявления `implements` нет. Новый адаптер для заказов использует тот же алгоритм.

`MatchSequence` объединяет источник с условием. Можно выбрать другой дизайн и передавать предикат отдельно, но тогда возникает вопрос: какого типа его аргумент, если элемент коллекции скрыт? Эта деталь является частью проектирования обобщённого API.

## Map тоже можно выразить через интерфейс

```go
type MappingJob interface {
    Len() int
    Apply(int)
}
```

```go
func RunMap(job MappingJob) {
	for i := 0; i < job.Len(); i++ {
		job.Apply(i)
	}
}
```

Адаптер `UserNameJob` хранит `Source []User`, `Target []string` и `Fn func(User) string`. Метод `Apply(i)` выполняет присваивание. Вызывающий создаёт результат, передаёт задание и получает заполненный срез обратно через своё значение `Target`. Полная реализация находится в [algorithms.go](../../examples/algorithms.go).

Это законное обобщение. Однако алгоритм `RunMap` не выражает отношение `[]E + func(E) R → []R`. Оно скрыто в конкретном адаптере. Ошибки в длине результата также остаются ответственностью адаптера. Мы сохранили типы локально, но не сделали универсальную типизированную сигнатуру Map.

## Почему Get() any не исправляет всё

Можно придумать интерфейс `Get(i int) interface{}`. Тогда алгоритм получает элементы, но тип, известный ему статически, — пустой интерфейс. Для typed callback нужно либо проверять динамический тип, либо вынести обработку назад в адаптер. Это уже другой компромисс, который разберём отдельно.

Также `Get() User` не реализует метод интерфейса `Get() interface{}`: сигнатуры методов должны совпадать. Возможность присвоить отдельный `User` в `interface{}` не означает ковариантности результатов методов.

## Где интерфейсы остаются правильным выбором

У `io.Reader` все реализации читают в `[]byte` и возвращают `(int, error)`. Здесь нет неизвестного отношения `E → R`, которое нужно выразить параметрами типов. Различается поведение источников. Интерфейс позволяет хранить разные реализации вместе и выбирать реализацию во время исполнения.

Такое обобщение часто называют поведенческим, а вызовы через интерфейс — динамическим полиморфизмом. Это описание модели языка: конкретный компилятор иногда устраняет косвенный вызов. Не следует превращать «интерфейс» в синоним «медленно». О выборе между интерфейсами и параметрами типов: [When To Use Generics](https://go.dev/blog/when-generics).

## Проверка понимания

Почему `sort.Interface` обходится без `Get`, а typed Map тяжело выразить таким же интерфейсом? Ответьте через набор операций алгоритма, а не через количество строк кода.
