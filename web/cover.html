Сначала задача, затем механизм

В каждой главе одна библиотека получает новое требование. Сравниваем не только тела функций: где проверяются типы, сколько кода нужно вызывающему и какие связи способен выразить API. Прежние главы о преобразованиях сохранены в справочной части этого же учебника.

Сквозной пример

Map: из пользователей в имена

Результат один — []string. Но путь к нему и гарантии на границе библиотеки различаются.

names := MapUserNames(users, name) // []string

Компилятор проверяет User → string. Для Order или другого результата нужна новая специализация.
