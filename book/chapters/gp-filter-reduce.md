# 21. Filter и Reduce: один договор для разных API

> Спроектируем результат, пустой вход и ошибку до выбора способа обобщения.

Код главы: [восемь вариантов](../../lessons/journey/approaches.go) · [generic-ядра](../../lessons/journey/generic.go) · [тесты договора](../../lessons/journey/contracts_test.go).

## Filter выбирает, а не преобразует

Map строит новое значение для каждого входного элемента. Filter сохраняет сами подходящие элементы в прежнем порядке. Дробь 2/4 остаётся 2/4; алгоритм не вызывает New и не сокращает поля.

Наш договор таков: nil-вход даёт nil-результат; любой ненулевой вход даёт ненулевой срез, даже если ничего не выбрано. Результат имеет отдельное хранилище элементов. При ошибке возвращаются ранее выбранные элементы, текущий и последующие не добавляются. Вместимость среза не входит в договор.

```go
func GenericFilter[E any](src []E, test func(E) (bool, error)) ([]E, error) {
	if src == nil {
		return nil, nil
	}
	out := make([]E, 0, len(src))
	for _, value := range src {
		matched, err := test(value)
		if err != nil {
			return out, err
		}
		if matched {
			out = append(out, value)
		}
	}
	return out, nil
}
```

При копировании Fraction копируются её числовые поля. Для произвольного E это неглубокая копия: если элемент содержит указатель или срез, объекты за ними могут остаться общими. Обещание отдельного результирующего среза не означает глубокое копирование графа данных.

## Почему true вместе с error не добавляет элемент

Предикат может вернуть (true, err). В нашем API это ошибка, а не совпадение. Ветвь обработки ошибки идёт первой, поэтому Filter сохраняет только уже принятый префикс результата. Частичный результат — не обязательно префикс входа: среди посещённых элементов могли быть отброшенные.

[Пример с ошибкой на втором элементе](../../lessons/journey/solutions_test.go) возвращает [1/2] и показывает ровно два вызова callback во всех восьми подходах. Третий элемент не посещается.

## Reduce меняет аккумулятор

В отличие от Filter, результат Reduce не обязан быть коллекцией. E — тип элемента, A — тип аккумулятора. Функция шага получает текущий A и очередной E, затем предлагает новое значение A.

```go
func GenericReduce[E, A any](src []E, initial A, step func(A, E) (A, error)) (A, error) {
	total := initial
	for _, value := range src {
		next, err := step(total, value)
		if err != nil {
			return total, err
		}
		total = next
	}
	return total, nil
}
```

Алгоритм фиксирует новое значение только после успешного шага. При ошибке возвращает последнее успешное. Для nil и пустого входа сохраняет initial; callback не вызывается. Свёртка идёт слева направо и не переставляет элементы.

Это не транзакция. Если A содержит изменяемый объект и step успел изменить его перед ошибкой, возврат прежнего значения переменной не отменит изменения объекта. Наши сравнения используют Fraction со значимыми числовыми полями; для указательного аккумулятора нужен отдельный договор о мутациях или копировании.

## Аккумулятор может иметь другой тип

```go
func ExampleGenericReduce() {
	values := []fraction.Fraction{{Numerator: 1, Denominator: 2}, {Numerator: 1, Denominator: 3}}
	text, err := journey.GenericReduce(values, "", func(total string, value fraction.Fraction) (string, error) {
		if err := value.Validate(); err != nil {
			return "", err
		}
		return strings.TrimPrefix(total+", "+value.String(), ", "), nil
	})
	fmt.Println(text, err)
	// Output: 1/2, 1/3 <nil>
}
```

Здесь E — Fraction, A — string. Следовательно, Reduce не является просто другим названием суммы. Sum — частный случай Reduce, где типы совпадают, а шагом служит Add.

В конкретном варианте этой главы A фиксирован как Fraction. Для строковой свёртки пришлось бы выпустить ещё одну специализацию или определить другой адаптер. GenericReduce и ReflectReduce способны выразить другую пару типов, но проверяют её в разное время.

## Как сохраняется договор у разных подходов

У замыкания результирующий срез и аккумулятор находятся в окружающем коде. У Selection и Fold — в полях адаптера. У interface{} нужны упаковка и извлечение. Reflection создаёт срез нужного динамического типа и проверяет сигнатуру шага. Сгенерированный и generic-код хранят типизированные локальные значения.

IteratorFilter выдаёт пары (E,error). Первая ошибка выдаётся один раз и завершает обход; значение E при ошибке не используется. Прекращение потребления тоже останавливает источник. Сам итератор не различает nil-срез и пустой срез, поэтому общий стенд сохраняет это различие при создании итогового хранилища, зная исходный срез.

## Проверка понимания

Нужно ли менять реализацию Filter, если результат должен разделять память с исходным срезом? Что произойдёт с обещанием об ошибке Reduce, если вместо Fraction аккумулятором станет *Money?
