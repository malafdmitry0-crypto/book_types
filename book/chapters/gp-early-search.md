# 8. Find, All и Any: один цикл для разных предметных условий

Код главы: [algorithms.go](../../algorithms/algorithms.go) · [example_test.go](../../algorithms/example_test.go) · [algorithms_test.go](../../algorithms/algorithms_test.go).


> Прочитаем реальную реализацию algorithms по шагам: где находятся данные, предикат и знание типа.

Протокол коллекции уже выбран. Теперь прочитаем законченный поиск: сначала цикл, затем адаптер, затем вызов и трассу. All и Any используют тот же договор, но по-разному останавливаются.

## Минимальный протокол

```go
type Predicate interface {
    Len() int
    Match(i int) (bool, error)
}
```

Predicate здесь означает коллекцию вместе с условием проверки. Название описывает её роль для алгоритма; это не функция, которая принимает неизвестный элемент. Мы сознательно объединили длину и условие в одном значении адаптера.

Исходник: [algorithms.go](../../algorithms/algorithms.go). Внешний контракт Find возвращает первый индекс, а не копию найденного объекта. Это позволяет не возвращать значение неизвестного типа.

## Алгоритм Find целиком

```go
func Find(data Predicate) (int, error) {
	n := data.Len()
	for i := 0; i < n; i++ {
		matched, err := data.Match(i)
		if err != nil {
			return -1, err
		}
		if matched {
			return i, nil
		}
	}
	return -1, nil
}
```

Проследим информацию в теле. Есть n и i типа int, matched типа bool и err типа error. Ни Fraction, ни Money, ни BoxInt там нет. Но найденный индекс можно использовать в исходном типизированном срезе вызывающего.

Сначала проверяется ошибка, затем matched. Нельзя трактовать пару `(true, err)` как успешное совпадение: операция уже сообщила, что результат недостоверен.

## Адаптер знает Fraction

```go
type fractionQuery struct {
    Values []fraction.Fraction
    Test   func(fraction.Fraction) (bool, error)
}

func (q fractionQuery) Len() int { return len(q.Values) }
func (q fractionQuery) Match(i int) (bool, error) {
    return q.Test(q.Values[i])
}
```

Test получает конкретную Fraction и может вызывать её методы. Предикат не обязан быть одинаковым у всех запросов: поле-функция позволяет менять условие без нового типа адаптера.

## Прочитаем fractionQuery буквально

В структуре два поля. Values хранит срез конкретных дробей. Test хранит функцию, которая принимает одну дробь и возвращает ответ вместе с возможной ошибкой. Тела функции в объявлении структуры нет: вызывающий передаст её при создании запроса.

Метод Len переводит запрос алгоритма «дай количество элементов» в обычный `len(q.Values)`.

Метод Match состоит из трёх действий. Его можно переписать более многословно, не меняя смысла:

```go
func (q fractionQuery) Match(i int) (bool, error) {
    value := q.Values[i]           // Получаем конкретную Fraction.
    matched, err := q.Test(value)  // Вызываем сохранённую функцию.
    return matched, err           // Возвращаем ответ алгоритму.
}
```

Это альтернативная запись того же метода; добавлять обе версии в один пакет нельзя.

Обратите внимание: Match не содержит цикла и не выбирает следующий индекс. Адаптер обслуживает один запрос. Цикл остаётся внутри Find.

## Как читать полный сценарий

В ExampleFind ниже сначала создаётся срез, затем функция isHalf, затем query с именованными полями. Только после этого вызывается Find. Читайте эти четыре шага отдельно: так видно, что условие относится к дроби, а цикл работает с индексами.

## Что происходит при передаче в интерфейс

Параметр data внутри Find имеет статический тип Predicate. В приведённом вызове передано значение конкретного типа fractionQuery. Упрощённо интерфейсное значение можно понимать как сочетание конкретного типа и значения этого типа.

```text
Find: data имеет статический тип Predicate
  конкретное значение: fractionQuery
    Values → срез дробей
    Test   → функция isHalf

data.Match(1)
  → метод fractionQuery.Match с получателем query
  → query.Values[1], то есть дробь 2/4
  → query.Test(эта дробь)
  → isHalf(эта дробь)
  → true, nil
```

Вызов метода интерфейса направляется к реализации конкретного значения. Find не пишет type switch и не выясняет, дроби перед ним или деньги. Его тело может использовать только операции, доступные через объявленный тип параметра: обратиться к `data.Values` или `data.Test` нельзя, потому что этих полей нет в контракте Predicate.

При передаче query по значению копируется значение структуры, включая описание среза. Элементы среза при этом не клонируются: исходный values и поле Values ссылаются на один базовый массив. Это не создание `[]interface{}` и не упаковка каждой дроби отдельно. Нужна ли для интерфейсного значения аллокация в куче, зависит от компилятора и контекста использования; сама схема этого не обещает.

## Зачем структура, если есть замыкание

Для этого же поиска можно использовать FindIndex из предыдущей главы:

```go
index, err := FindIndex(len(values), func(i int) (bool, error) {
    return isHalf(values[i])
})
```

Замыкание делает ту же работу, что Match: связывает индекс с конкретным значением. **Для простого Find отдельный адаптер не обязателен.** Он нужен именно потому, что наш выбранный API принимает Predicate.

| Вариант | Как данные связаны с алгоритмом | Что приходится согласовать |
|---|---|---|
| FindIndex(n, test) | Замыкание захватывает values и условие | Отдельно переданная длина должна соответствовать срезу |
| Find(query) | Методы адаптера обращаются к его полям | Len и Match должны работать с согласованными данными |
| Конкретный FindFractionFunc | Срез и callback прямо указаны в сигнатуре | Эта функция поддерживает только Fraction |

Адаптер собирает операции в один объект, который можно передать в Find, All и Any. Это полезно для повторного использования одного запроса и особенно для протоколов с несколькими операциями, как Len, Compare и Swap. Но компилятор всё равно не доказывает, что методы обращаются к одному и тому же срезу: это ответственность реализации.

В простом локальном поиске замыкание часто понятнее. Не нужно создавать структуру ради самого слова «интерфейс». Сначала выбирают, какие данные и операции должны пересекать границу библиотеки, затем — удобную форму API.

Полный исполняемый вариант без структуры-адаптера вынесен отдельно: [код и объяснение](../../algorithms/closures/README.md), [два примера вызова](../../algorithms/closures/example_test.go).

## Что адаптер не делает за нас

fractionQuery не проверяет границы индекса, не исправляет дроби и не создаёт функцию Test автоматически. Если Test равен nil, вызов Match паникует. Если индекс выходит за пределы Values, индексирование паникует. Наш Find вычисляет индексы по Len; адаптер и callback должны сохранять согласованность коллекции во время обхода.

Методы здесь используют получатель по значению, поскольку им не нужно заменять поля query. Поэтому интерфейсу удовлетворяют и fractionQuery, и *fractionQuery. Для moneySum в следующей главе потребуется изменять поле Total, и там получатель будет указателем.

Проверяемый пример из [example_test.go](../../algorithms/example_test.go):

```go
func ExampleFind() {
	// 1. Данные и условие поиска.
	values := []fraction.Fraction{
		{Numerator: 1, Denominator: 3},
		{Numerator: 2, Denominator: 4},
		{Numerator: 3, Denominator: 4},
	}
	half := fraction.Fraction{Numerator: 1, Denominator: 2}
	isHalf := func(value fraction.Fraction) (bool, error) {
		if err := value.Validate(); err != nil {
			return false, err
		}
		return value.Equal(half), nil
	}

	// 2. Адаптер связывает срез и условие с методами Len и Match.
	query := fractionQuery{Values: values, Test: isHalf}

	// 3. Алгоритм видит только интерфейс адаптера.
	index, err := algorithms.Find(query)
	if err != nil {
		fmt.Println("Ошибка:", err)
		return
	}
	if index == -1 {
		fmt.Println("Совпадений нет")
		return
	}

	// 4. Найденное значение берём из исходного типизированного среза.
	fmt.Println("Индекс:", index)
	fmt.Println("Дробь:", values[index])
	// Output:
	// Индекс: 1
	// Дробь: 1/2
}
```

Ожидаемый индекс — 1, потому что элемент `2/4` математически равен `1/2`. Поиск ничего не знает о сокращении дробей: это знание остаётся в Fraction.Equal.

Здесь target заведомо корректен по литералу, а каждый посещённый элемент проходит Validate. Если target приходит извне, его тоже нужно проверить перед поиском: сама Equal для невалидных значений возвращает false, а не error.

## Трасса одного вызова

```text
Find(query)
  → query.Len() = 3
  → query.Match(0)
      → Test(Fraction{1, 3})
      → Equal(1/2) = false
  → query.Match(1)
      → Test(Fraction{2, 4})
      → Equal(1/2) = true
  → return 1, nil

Match(2) уже не вызывается.
```

Эта трасса показывает два независимых решения: алгоритм управляет остановкой; предикат выбирает смысл совпадения.

## All использует тот же интерфейс

```go
func All(data Predicate) (bool, error) {
	n := data.Len()
	for i := 0; i < n; i++ {
		matched, err := data.Match(i)
		if err != nil {
			return false, err
		}
		if !matched {
			return false, nil
		}
	}
	return true, nil
}
```

Для пустой коллекции цикл не выполняется, результат true. Это договор «нет элемента, опровергающего условие». При первом false работа прекращается; callback после этого не вызываются.

```go
func ExampleAll() {
	values := []fraction.Fraction{
		{Numerator: 1, Denominator: 3},
		{Numerator: 2, Denominator: 4},
	}
	zero := fraction.Fraction{Denominator: 1}
	isPositive := func(value fraction.Fraction) (bool, error) {
		comparison, err := value.Compare(zero)
		return comparison > 0, err
	}
	query := fractionQuery{Values: values, Test: isPositive}

	positive, err := algorithms.All(query)
	if err != nil {
		fmt.Println("Ошибка:", err)
		return
	}
	fmt.Println("Все положительные:", positive)
	// Output: Все положительные: true
}
```

Мы использовали Compare с корректной дробью 0/1. Сам All не требует, чтобы у элементов был Compare: вместо него Test мог бы проверять формат строки, доступность ресурса или другое условие.

## Any выражается через Find

```go
func Any(data Predicate) (bool, error) {
	index, err := Find(data)
	return index >= 0, err
}
```

Тут переиспользуется уже не только протокол коллекции, но и готовый алгоритм. Пустой вход даёт false, первое совпадение завершает работу. При ошибке Find возвращает -1, поэтому Any возвращает false вместе с той же ошибкой.

## Добавляем другой тип без изменения algorithms

Для Money можно написать moneyQuery с `Values []money.Money` и `Test func(money.Money) (bool, error)`. Методы Len и Match будут почти такими же. После этого тот же Find найдёт сумму нужной валюты, а All проверит, что все суммы неотрицательны.

Компилятор проверит конкретный callback внутри moneyQuery. Цена подхода — повторение небольшого адаптера. Мы не избавились от всех различий типов; мы локализовали их вне библиотечного обхода.
