# 14. Go 1.18: связи типов становятся частью сигнатуры

Код главы: [generic.go](../../lessons/generic/generic.go) · [example_test.go](../../lessons/generic/example_test.go) · [example_test.go](../../examples/example_test.go).


> Параметры типов позволяют опубликовать один алгоритм с согласованными типами входа, callback и результата.

Теперь доходим до изменения самого языка: Go 1.18. Параметры типов позволяют записать связь входа и результата в сигнатуре. Сначала сравним простой Find/Map, затем вернём ошибки и начальное значение нашей суммы.

## Find и All: тип известен, но произволен

Первая часть закончилась работающей библиотекой algorithms: общего обхода удалось добиться через адаптеры, а типы результатов остались у вызывающего. Параметры типов позволяют выразить некоторые из этих связей прямо в сигнатуре. Сначала рассмотрим сохранённые упрощённые функции из examples над User; затем вернёмся к контрактам ошибок Fraction и Money.

```go
func Find[E any](src []E, pred func(E) bool) int {
	for i, item := range src {
		if pred(item) {
			return i
		}
	}
	return -1
}
```

```go
func All[E any](src []E, pred func(E) bool) bool {
	for _, item := range src {
		if !pred(item) {
			return false
		}
	}
	return true
}
```

`E` — не интерфейсная коробка вокруг каждого элемента. При конкретном вызове он обозначает выбранный тип. Тело алгоритма проверяется с учётом ограничения: при `any` оно может передавать `E` в `func(E) bool`, но не может произвольно складывать значения или читать у них поле `Age`.

```go
index := Find(users, adult)
all := All(users, active)
textIndex := Find([]string{"go", "generic"}, func(s string) bool {
    return len(s) > 2
})
```

Один исходник работает для `User`, `string` и новых пользовательских типов. Цикл и условия остановки проверяются в одном месте; предметные предикаты остаются обычными типизированными функциями.

## Map: недостающее отношение E → R

```go
func Map[E, R any](src []E, transform func(E) R) []R {
	if src == nil {
		return nil
	}
	out := make([]R, len(src))
	for i, item := range src {
		out[i] = transform(item)
	}
	return out
}
```

```go
names := Map(users, name) // []string
ages := Map(users, func(u User) int { return u.Age }) // []int

// Map(users, func(s string) int { return len(s) })
// Ошибка компиляции: []User и параметр string не согласованы.
```

Компилятор связывает `E` с элементом первого аргумента и входом callback; `R` — с выходом callback и элементом результата. Теперь то, что reflection проверял при исполнении, выражено на границе функции.

Для `[]User` и `func(User) string` никакие преобразования `User → interface{}` и `interface{} → string` не требуются. Вывод аргументов типов сокращает запись, но не меняет смысл: можно написать `Map[User, string](users, name)` явно.

## any в ограничении и any как тип значения

Сравните:

```text
MapAny([]interface{}, func(interface{}) interface{}) []interface{}
Map[E, R any]([]E, func(E) R) []R
```

В первой сигнатуре один и тот же интерфейсный тип принимает значения разных динамических типов. Во второй `any` ограничивает допустимые аргументы типов, а `E` и `R` сохраняют конкретные выбранные типы в сигнатуре.

Вызов `Map[any, any]` возможен и будет работать с интерфейсными элементами. Дженерики не запрещают динамику; они позволяют не вводить её туда, где нужна типизированная однородная коллекция.

## Что компилятор гарантирует, а что нет

| Гарантия | Есть? |
|---|---|
| Callback принимает элемент согласованного типа | Да |
| Результат содержит значения выходного типа callback | Да |
| Callback не паникует | Нет |
| Callback чистый и не меняет общие объекты | Нет |
| Алгоритм не ошибся в границах цикла | Нет, нужны тесты |
| Map сохраняет nil и порядок | Это контракт нашей реализации, не свойство дженериков |
| Код автоматически быстрее интерфейсного аналога | Такой гарантии язык не даёт |

Нужно различать статическую проверку generic-функции и стратегию машинной реализации. Язык не требует от компилятора генерировать отдельную полную копию для каждой возможной комбинации типов и не обещает устранить стоимость callback. Описание введения параметров типов: [Go 1.18](https://go.dev/doc/go1.18#language), [An Introduction To Generics](https://go.dev/blog/intro-generics).

## Дженерики не заменили интерфейсы

### Продолжение нашей ранней библиотеки с сохранением ошибок

Для Sum теперь можно потребовать метод сложения с тем же типом. Следующий код реализован в lessons/generic и продолжает API с сохранением ошибок:

```go
type Addable[T any] interface {
    Add(T) (T, error)
}

func SumValues[T Addable[T]](values []T, initial T) (T, error) {
    total := initial
    for _, value := range values {
        next, err := total.Add(value)
        if err != nil {
            return total, err
        }
        total = next
    }
    return total, nil
}
```

Теперь связь с собственным типом присутствует в интерфейсе Addable[T]. Money.Add и Fraction.Add подходят для разных инстанциаций без коллекционного адаптера с Add(index). Но initial по-прежнему задаёт вызывающий: для Money нужна валюта, для Fraction — корректный 0/1. Параметры типов не доказывают, что нулевое значение структуры является нейтральным элементом сложения.

Для Map можно вернуть конкретный []R и одновременно сохранить возврат ошибок:

```go
func MapValues[E, R any](values []E, transform func(E) (R, error)) ([]R, error) {
    if values == nil {
        return nil, nil
    }
    out := make([]R, len(values))
    for i, value := range values {
        result, err := transform(value)
        if err != nil {
            return out, err
        }
        out[i] = result
    }
    return out, nil
}
```

Здесь выбран полный буфер результата: при ошибке заполненный префикс сохраняется, оставшийся суффикс содержит нулевые R. Это явное решение API. В раннем Mapping вызывающий сам выбирал хранилище; новый вариант берёт выделение памяти на себя. Нельзя объяснять переход к generics только уменьшением числа строк и незаметно менять договор о результате.

### Что остаётся у интерфейсов

Find с предикатом не нуждается в методах у `E`: операцию предоставляет callback. Если задача по смыслу требует `Read`, интерфейс `io.Reader` остаётся хорошим контрактом. Если нужно одновременно сохранить конкретный тип и потребовать метод, эти два механизма можно сочетать — следующая глава именно об этом.
