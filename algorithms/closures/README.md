# Альтернатива: поиск без структуры-адаптера

Вариант из ранней модели Go: передать длину и функцию от индекса. Полный код — в [find.go](find.go), два самостоятельных сценария — в [example_test.go](example_test.go).

## Что изменилось

В интерфейсном варианте мы создавали fractionQuery:

```go
query := fractionQuery{Values: values, Test: isHalf}
index, err := algorithms.Find(query)
```

Find обращался к query.Len() и query.Match(i). Методы переводили эти вызовы в len(values) и isHalf(values[i]).

Теперь передаём те же операции напрямую:

```go
index, err := closures.FindIndex(len(values), func(i int) (bool, error) {
    return isHalf(values[i])
})
```

Функция внутри аргумента — замыкание: она использует values и isHalf из окружающего кода. Когда FindIndex передаёт ей индекс, она извлекает дробь и проверяет условие. Структуры fractionQuery и методов Len/Match в этом варианте нет.

| Интерфейсный вариант | Вариант с замыканием |
|---|---|
| query.Values | values, доступный замыканию |
| query.Test | isHalf, доступная замыканию |
| query.Len() | Отдельный аргумент len(values) |
| query.Match(i) | Вызов переданной функции test(i) |

Адаптация остаётся как действие: перевести индекс в операцию над значением. Но для неё не нужен отдельный именованный тип.

## Почему алгоритм остаётся общим

FindIndex принимает только int и func(int) (bool, error). Он не знает ни Fraction, ни Money. Для денег в example_test.go передано другое замыкание, а библиотечный цикл используется тот же. Дженерики, reflection и interface{} здесь не нужны.

Результат по-прежнему индекс. Вызывающий берёт values[index] из своего типизированного среза после проверки ошибки и отсутствия совпадения. Преобразования типа результата нет.

## Когда какой вариант удобнее

Для короткого локального поиска замыкание требует меньше объявлений, а данные и условие видны рядом с вызовом. Отдельно переданная длина должна соответствовать захваченному срезу; компилятор этого не проверяет.

Интерфейсный адаптер полезен, когда хочется передавать согласованные операции одним значением, повторно использовать его или дать ему имя. Особенно это заметно при нескольких операциях, как Len, Compare и Swap. Но наличие интерфейса само по себе не гарантирует согласованности методов.

Оба подхода относятся к одной модели языка. Это две формы API, а не обязательные последовательные стадии разработки.

## Контракт и запуск

Поиск идёт слева направо, останавливается на первом совпадении или ошибке. Отсутствие совпадения и ошибка дают индекс -1; отличает их error. Для пустого входа callback не вызывается. Длина должна быть неотрицательной, callback должен поддерживать все переданные индексы. Паники не перехватываются.

Из корня проекта:

```sh
go test ./algorithms/closures -run Example -v
go test ./algorithms/closures
```

Go проверит вывод по комментариям Output. При успешном запуске он показывает статусы примеров, а не их stdout. Ожидаемые результаты находятся внизу каждого сценария.
