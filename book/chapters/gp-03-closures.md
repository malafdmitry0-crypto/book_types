# 4. Индексы и замыкания: элемент остаётся у вызывающего

Код главы: [find.go](../../algorithms/closures/find.go) · [example_test.go](../../algorithms/closures/example_test.go) · [map_test.go](../../algorithms/closures/map_test.go).


> Ранний Go позволял исключить неизвестный тип из сигнатуры, передав алгоритму операцию над индексом.

Find возвращает индекс. Значит, он может вообще не получать элемент: достаточно спросить, подходит ли позиция. Проверим эту идею сначала на поиске, затем на записи результата Map.

## Линейный поиск только по позициям

```go
func FindIndex(n int, test func(int) (bool, error)) (int, error) {
    for i := 0; i < n; i++ {
        matched, err := test(i)
        if err != nil {
            return -1, err
        }
        if matched {
            return i, nil
        }
    }
    return -1, nil
}
```

Этот вариант теперь можно запустить отдельно: [реализация FindIndex](../../algorithms/closures/find.go), [примеры для дробей и денег](../../algorithms/closures/example_test.go), [объяснение альтернативы](../../algorithms/closures/README.md). Импорт — gotypes/algorithms/closures, вызов — closures.FindIndex. В основном пакете algorithms длина и проверка объединены в интерфейсном объекте.

```go
half := fraction.Fraction{Numerator: 1, Denominator: 2}
index, err := FindIndex(len(values), func(i int) (bool, error) {
    if err := values[i].Validate(); err != nil {
        return false, err
    }
    return values[i].Equal(half), nil
})
```

Тип `values` — `[]Fraction`, известный замыканию. FindIndex получает только int, bool и error. Для денег меняется замыкание, а библиотечный цикл сохраняется. Нет упаковки элементов в interface{} и нет runtime-исследования их типов.

Это уже типобезопасное обобщение поведения и данных, но информация о данных находится **за** границей алгоритма. Сигнатура не сообщает, что n является длиной именно той коллекции, которую индексирует test.

## Настоящий образец: sort.Search

Стандартный `sort.Search` тоже принимает размер и функцию от индекса. Он выполняет бинарный поиск границы, где монотонный предикат меняется с false на true. Результат отсутствия границы — n, а не -1.

```go
// import "sort"
values := []int{2, 5, 9, 12}
index := sort.Search(len(values), func(i int) bool {
    return values[i] >= 8
}) // 2
```

Привязка к данным находится в замыкании, сам Search не знает тип элементов. Этот API иллюстрирует, почему далеко не каждой полезной обобщённой функции необходим параметр E. Правила поиска: [sort.Search](https://pkg.go.dev/sort#Search).

Наш FindIndex нельзя заменить на бинарный Search для произвольных дробей: условие «равен 1/2» не обязано быть монотонным. Важнее сходства сигнатур — предусловия конкретного алгоритма.

## Map через замыкание записи

```go
func MapIndex(n int, apply func(int) error) error {
    for i := 0; i < n; i++ {
        if err := apply(i); err != nil {
            return err
        }
    }
    return nil
}
```

```go
var texts []string
if values != nil {
    texts = make([]string, len(values))
}
err := MapIndex(len(values), func(i int) error {
    if err := values[i].Validate(); err != nil {
        return err
    }
    texts[i] = values[i].String()
    return nil
})
```

Создание результата и преобразование остаются конкретно типизированными. Но MapIndex организует только цикл: он не может сам выбрать тип и создать `[]string`, потому что не получает сведений о связи входа и выхода.

Если texts короче n, запись за пределами среза вызовет панику внутри callback, а не ошибку в результате. Если ошибка преобразования произошла посередине, заполненный префикс сохраняется. Это не последствия интерфейсов или reflection — они возникли уже на уровне договора индексного API.

## Почему следующим шагом станет объект операций

Мы передаём несколько согласованных частей: размер, исходные данные, предикат или функцию записи. Их можно связать в один адаптер с методами. Тогда алгоритм сможет попросить минимальный набор операций, а вызывающий — реализовать их конкретным типом.

Обе формы были доступны в одной исторической модели языка. Переход от замыкания к интерфейсу в учебнике — изменение организации программы, а не очередной релиз Go.
